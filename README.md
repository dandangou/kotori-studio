# 烤肉工房 / Kotori Studio

在 Mac 上完成 **长直播找片 → 日语识别 → 中文初译 → 校对打轴 → 切片与字幕导出** 的本地工作台。为 Apple Silicon / 16 GB 内存配置设计，界面是浏览器，本机 Python 服务负责处理；视频和模型无需交给云端服务。

## 支持平台与首次安装

当前版本面向 **macOS + Apple Silicon（M1 或更新）**，建议 16 GB 内存；Windows、Linux、Intel Mac 的完整流程尚不支持。源码不包含视频、字幕项目、模型、Python 环境或 FFmpeg 二进制。

1. 下载本仓库源码 ZIP 并解压，或通过 Git 克隆。
2. 确保有 Apple Silicon 版 Python 3.12 或 3.13。在终端进入解压目录（例如 `cd ~/Downloads/kotori-studio-main`），运行 `bash scripts/setup.sh`。首次安装需要网络，会下载 Python 依赖和经过哈希校验的 FFmpeg / FFprobe。
3. 双击 `启动烤肉工房.command`；也可以运行 `.venv/bin/python scripts/launch.py`。
4. 在「模型与设置」中按需下载模型，随后识别和翻译可以离线运行。先点「体验演示项目」检查字幕编辑与视频导出，无需先下载模型。

从 YouTube 下载还需要已安装的 Node.js（供 yt-dlp 解析视频使用）以及能够访问 YouTube 的网络。已有本地视频时无需使用这一功能。源码版不要求 Codex、云端账号或付费 API。

默认模型下载量合计约 3.6 GiB，建议至少预留 15 GiB；长直播视频和导出另计。安装脚本仅在项目目录安装依赖，不修改系统 Python。

## 启动

在 Finder 中双击 **`启动烤肉工房.command`**，浏览器会打开 **http://127.0.0.1:8765**。启动器重复打开时会复用本项目服务。只有当前电脑能连接这个地址。

不使用时双击 **`停止烤肉工房.command`** 关闭本地服务；关闭浏览器标签页本身不会停止后台任务。

首次使用可以点击「体验演示项目」，练习字幕操作。演示画面及文字在本机生成，**不是 hololive 素材，也不是模型识别的成绩展示**。

开发者启动：

```bash
cd /path/to/kotori-studio
.venv/bin/python scripts/launch.py
```

环境缺失时运行 `bash scripts/setup.sh`。依赖固定在 `requirements.txt`，FFmpeg 和 FFprobe 放在 `.runtime/bin/`，Python 依赖放在 `.venv/`。启动和处理日志在 `data/logs/` 与 `data/jobs/`。

## 建议工作流程

1. **导入。**「选择本地视频」直接引用文件，不复制几个 GB 的原片；拖入 / 上传导入会创建一份副本。也可以输入单个 YouTube 公开回放链接并选择下载分辨率。下载需要本机能正常访问 YouTube，网站验证或网络限制会直接显示错误。
2. **设置直播模式和术语。**游戏模式偏向突然反应、反差和音量变化；杂谈 / 联动偏向故事和互动；综合模式兼顾；歌回 / 演唱会模式让语义分析优先关注歌曲之间的讲话、惊喜和互动，并提示模型区分歌词与真实经历。项目资料里填写原直播标题、链接及 `日文=中文` 术语表，补充你常烤的成员、昵称和游戏名。
3. **快速找片。**先流式分析音轨，返回不重叠的候选片段并保留上下文。已有字幕时也会使用关键词和对话密度。每条候选显示依据。试听后「保存为切片」，即可在「我的切片」里管理并分别导出。
4. **识别。**先对最有希望的选区运行 Whisper turbo；需要完整语义筛选时先识别全片，再点「语义选片」。难句可以安装 large-v3 后对局部重新识别。识别会替换选区内字幕，已有人工修改建议先导出 SRT。
5. **初译。**默认本地 Qwen3 4B，按小组结合前文和术语表生成中文草稿。默认跳过已有译文，不自动标记校对完成。可选自己的 OpenAI 兼容接口，只发送所选字幕文本、必要前文和术语，不发送视频或音频。
6. **校对与打轴。**对照日文和中文编辑，点击字幕编号定位；波形可以点击跳转，放大后拖动当前字幕边缘调整时间。桌面宽窗口可打开「专注校对」，让视频、波形和独立滚动的字幕区同时显示。支持循环选区、0.5–2 倍速、增删、拆分、合并、撤销和已校对标记。「偏移时间」可将所有字幕、选区或单条字幕统一提前 / 延后，精度为 1 毫秒。长字幕列表每页显示 120 条。
7. **导出。**SRT、带基础双语样式的 ASS、纯 MP4 切片、烧录字幕的 MP4；中文字幕在上，日文在下。字幕自动截断到选区，并换算成从 0 开始的时间。视频使用原始素材准确裁剪，优先 M3 VideoToolbox 硬件编码，不能使用时回退软件编码。视频旁会生成来源与原片区间说明文本。

## 快捷键

输入文字时保留系统文字编辑快捷键；非输入状态下：

| 按键 | 操作 |
| --- | --- |
| 空格 | 播放 / 暂停 |
| ← / → | 后退 / 前进 2 秒 |
| Shift + ← / → | 后退 / 前进 0.1 秒 |
| I / O | 在播放位置设选区入点 / 出点 |
| Alt / ⌥ + I / O | 将选中字幕入点 / 出点设为播放位置 |
| [ / ] | 上一条 / 下一条字幕 |
| ⌘S | 保存 |
| ⌘Z | 撤销字幕修改 |

没有词级信息的字幕，拆分文字会按时间比例估算，拆分后请确认文字分界。词级时间来自 ASR 对齐，不等于帧级人工打轴。

## 离线模型和内存

| 用途 | 模型 | 下载量（约） |
| --- | --- | --- |
| 默认日语 ASR | MLX Whisper large-v3-turbo | 1.5 GiB |
| 可选难句复核 | MLX Whisper large-v3 | 2.9 GiB |
| 中文初译、语义候选 | MLX Qwen3-4B-Instruct-2507 4bit | 2.1 GiB |

「模型与设置」显示实际安装状态。下载源可显式选择 Hugging Face 或 hf-mirror.com；镜像只用于下载公开模型文件。模型下载后保存在本机；仓库不会附带权重。处理任务只使用已缓存模型，不会暗中联网下载。也可以手动运行：

```bash
.venv/bin/python scripts/download_models.py turbo qwen3-4b
# 本机无法访问 Hugging Face 时，可自行选用镜像：
.venv/bin/python scripts/download_models.py turbo qwen3-4b --endpoint https://hf-mirror.com
```

ASR 与语言模型使用独立子进程串行运行，完成后释放 GPU 内存。ASR 每次读取约 4 分钟音频，避免把两小时音轨及频谱同时放入内存；已完成的分段写入缓存，取消或中断后重新运行**相同模型、术语与范围**会复用结果。改变源文件或术语时会生成新的缓存。初译也缓存已完成的字幕小组。

M3 Air 为无风扇机型，长时间推理受温度、同时打开的程序、模型及视频内容影响。短测试的速度不能直接当作整场直播的耗时保证。

## 多段拼接与翻译

1. 在候选面板选择「完整故事」或「短视频」，点「语义选片」，再把需要的候选「加入拼接」。也可以手动设置原片选区，在「拼接成片」中加入。
2. 清单中的入点 / 出点始终是原片时间；可以改时间、上下调整顺序或移除某段。「查看 / 翻译」回到这段对应的字幕。
3. 去掉插入的 superchat：先在原片设置那段插话的入点与出点，再打开清单点「剔除当前选区」。原有一段会分成前后两段，源视频和原字幕保留。与故事有关的 superchat 应保留，请连播确认。
4. 「连播清单」会跳过被删部分；浏览器预览为近似转场，最终导出使用 FFmpeg。「导出拼接成片」生成一个 MP4，或时间已经重排的 SRT / ASS。候选面板的批量导出仍是每个候选一个文件。
5. 直接在原片字幕的中文栏翻译即可。导出时先按每段裁切字幕，再按累计成片时长排列，不需要重新打轴；每个视频附带按播放顺序列出的来源区间。

初译读取视频标题、术语和前后字幕作为语境，默认跳过已有译文。识别错误和叠声仍需听校；字幕只有经过人工确认后才应标记为已校对。

## 存储与备份

- `data/projects/<项目 ID>/project.json`：字幕、时间轴、候选片段、术语、来源资料。保存采用原子替换和版本号，后台结果不会静默覆盖期间手动修改的字幕。
- `data/models/hub/`：共享离线模型。多个项目共用一份。
- `data/cache/<项目 ID>/`：识别中间文件、断点、翻译缓存及播放代理。
- `data/exports/<项目 ID>/`：最终导出文件。
- `data/imports/`：上传 / YouTube 导入产生的媒体。通过本地路径导入的源文件仍在原处。
- `data/jobs/`：任务状态、结果与日志。应用退出后，未完成任务显示中断，需要重新提交；不会在重启时自动重新下载或发送 API 请求。

主要空间开销取决于视频数量与输出码率。2 小时、8 Mbps 视频约 7.2 GB；默认不额外做整片代理，无法直接播放时才按需生成 720p 代理。清理按钮只删除可重建的音频与代理，保留源视频、字幕、断点和输出。中途取消的视频下载可能保留 `.part`，可在 `data/imports/` 中确认后自行清理。

备份请复制 `data/projects/` 和需要保留的 `data/exports/`，同时保留对应源视频。整个项目文件夹可以移到外置 SSD，但原片的绝对路径仍需有效；移动环境后可能需要重建 `.venv`。

识别排队期间如果你又修改了同范围字幕，任务会停止以保留人工修改。后台识别替换了某条字幕，而浏览器仍有尚未保存的输入时，界面会保留为本机可恢复草稿，支持恢复或下载；它不会静默混进新识别结果。草稿在当前浏览器的本地存储中，清除浏览器数据会删除这些草稿。

## 准确性边界

快速选片结合每个时刻相对附近音量的变化、动态程度及已有字幕的关键词 / 对话覆盖率。新导入的 YouTube 回放若提供公开的重复观看热度，会随项目保存，作为 30% 的辅助评分；另外 70% 来自原有音频 / 字幕评分。缺少热度的本地视频使用原算法，不需要额外 API。这个权重是尚未通过标注集校准的启发式，热度和排序分都不是正确率。

「语义选片」提供完整故事、短视频和连续片段三种目标。完整故事先按字幕梳理事件，允许用多个保留区间跳过无关插话，再用事件摘要寻找跨时段后续。短视频软性偏好 60–120 秒，超时会降低排序，但不会强行截断；完整故事没有 120 秒的硬上限。连续片段模式保留原来的最短 / 最长时长限制。短视频是时长策略，导出画幅沿用原片。

故事编排只覆盖已经识别或导入的字幕。全局关联目前最多分析排序靠前的 40 个事件摘要，每个成片最多 32 段；超长档案可能漏掉低排名的呼应。模型会误判人名、玩笑和因果，不能把候选理由当成事实。热度辅助、人工筛选以及模型推理是不同步骤，不能把人工调整后的切片当作全自动选片的成绩。

**“音量大”不等于“好片段”。**快速找片是候选生成，不是理解了整场直播；语义选片读的是字幕，不具备画面理解能力。安静但有趣的情节、视觉笑点、细微梗、多人同时讲话、歌声和游戏音效都可能漏检或误判。

低置信度提示来自 ASR 的启发式统计，并不是校准后的正确率。声音重叠目前没有自动说话人分离。人名、梗和省略句尤其需要人工复核。4B 本地模型的初译用于减少重复输入，不能替代熟悉日语和主播语境的校对。仅以少量合成素材的识别成功，不能声称真实直播的准确率已获验证。

此版本没有自动上传 B 站，也没有复杂特效字幕、画面理解、聊天弹幕高潮分析或多人音轨分离。ASS 可继续在 Aegisub 等工具中做高级排版。

实际操作时，ASR 已经给每条日文填写 IN / OUT，填写或修改中文不会改动时间。点字幕编号定位句首；需要修轴时放大波形到 15 秒，选中字幕后拖动两端，或用 Alt / ⌥ + I / O 设置起止位置（先退出文字输入框）。自动断句不合适则合并 / 拆分，疑难处用循环选区和慢速播放复听。

## 角色配色与齐声

项目顶部「角色配色」可修改角色名、颜色，或新增角色。当前预设为天音彼方（蓝）、雪花菈米（浅蓝）、戌神沁音（棕黄）、AZKi（红）。每条字幕的时间框下勾选说话人：单人使用纯色，多人齐声使用每个字内的横向分色，颜色顺序按勾选顺序；未选角色保持白色。配色修改会应用到该项目所有使用这些角色的字幕。最多定义 24 位角色，每句最多选择 8 位。

预览、ASS 与烧录 MP4 支持颜色；SRT 保留纯文字和时间。齐声 ASS 用相同位置的分层裁切文字保留黑色描边，在默认 Heiti SC / 52 字号下设计；若用其他工具改变字体和字号，需要重新调整裁切带。不同说话人的字幕合并前需要统一选择，拆分字幕继承原来的说话人。当前不自动辨认声纹，需要编辑者选择说话人。

## 一场直播，多部切片

在「我的切片」中选择「新建切片」，填写名称，保存当前连续选区或全部拼接段落。已有切片可载入编辑、更新范围或单独导出；批量导出会使用各自名称分别生成视频 / 字幕文件。修改拼接后需要更新对应切片，已经导出的文件不会自动变化。

所有切片共用原片字幕、时间轴和角色配色，重叠内容校对一次即可复用。重新找片会保留已保存的切片。

## 分辨率

导出默认保留原片分辨率，也可选择最高 480p / 720p / 1080p / 1440p / 2160p；保持比例并且不放大低分辨率原片。选择 1080p 不会把 480p 变成真正高清。需要高清成片时，在导入阶段下载 1080p 原片。浏览器播放代理仅用于预览，导出仍读取原片。
